## 结论

本阶段完成差异审计，**不新增 `env.js`**。虽然 Test / Prod 的基础环境开关可以抽取，但两边的可靠性层、镜像库与同步初始化已经发生实质分叉；在未先完成 Prod 结构迁移和回归验证前，直接抽取配置会扩大风险。

阶段 B 应先将 Prod 机械迁移为 `index.html`、`styles.css`、`app.js`，再用最小环境配置层承载已确认的环境差异。

## 已确认差异

### 必须保留的生产环境差异

1. Prod 使用无前缀的 localStorage；Test 必须保持 `wbtest_` 前缀，避免同源页面互相读取数据。
2. Prod 可以进行 Gist 同步、账户登录和刷新后的登录提示；Test 必须保持同步禁用，不能连接正式云库。
3. Prod 保存正式账户默认配置；Test 不应内置正式账户或任何可用凭据。
4. Prod 当前 IndexedDB 镜像命名及可靠性层与 Test 不同。迁移前不得覆盖或清理 Prod 的镜像数据。

### 可抽取为环境配置的差异

后续在两边结构一致后，可由 `env.js`（或同等的加载前配置）管理：

- `isTestBuild`
- `storageNamespace`
- `indexedDbName` / 镜像环境标识
- `cloudSyncEnabled`
- 是否允许读取默认账户配置
- 测试版标识文案

配置文件只提供环境值；业务代码仍保留相同的存储、导入导出、登录和同步调用点。Prod 配置文件属于环境专属文件，发布时不得被 Test 版本覆盖。

### 暂不安全判断或迁移的差异

1. Prod 的可靠性与 IndexedDB 实现仍是旧版本；不能据此判断可以直接替换为 Test v2。
2. Prod 的 `initSync()` 在初始化时补齐默认账户；Test 在测试构建下提前退出。该顺序必须在 Prod 迁移后的浏览器回归中保留验证。
3. Prod 源码中存在默认账户敏感凭据。用户已明确这是个人使用项目，并接受维持现状的风险；因此本轮不轮换、不迁移、不复制到 Test，也不把此项作为阶段 B 的阻塞条件。

## 推荐阶段 B 迁移方案

1. 重新获取 Prod 最新提交并创建可回滚备份点。

3. `index.html` 仅改为引用拆出的 `styles.css` / `app.js`，保持原有 DOM 结构、脚本顺序和正式环境行为。
4. 本阶段不新增 `env.js`；等三文件迁移通过 Review 和浏览器回归后，再进入最小环境配置层。
5. 在隔离浏览器数据中验证：刷新登录提示、正式 localStorage、镜像恢复、导入导出、Gist 登录与同步。
