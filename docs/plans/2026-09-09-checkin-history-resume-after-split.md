## 阶段 B — 断签备注 + 打卡记录图

对应原 Plan：Task 3 + Task 4。

建议分支：

`codex/checkin-history-phase-b`

### 目标

把“断签备注”和“打卡记录图”作为一个完整用户体验阶段完成，减少重复打开同一批打卡数据、日期详情、热力区域代码的成本。

### B1. 断签备注

要求：

- 点击历史断签日期可以查看详情。
- 支持添加、编辑、删除断签备注。
- 备注按 `YYYY-MM-DD` 日期键保存。
- 优先使用原 Plan 建议的轻量兼容字段；实际字段名需先确认当前 `S` 命名风格。
- 老数据没有该字段时必须正常工作。
- 保存后历史列表/日期详情立即更新。
- 删除备注只删除备注，不改变打卡事实。
- 检查现有整份 `S` 序列化是否会自然携带该字段；如果可以，不修改 Gist 协议。

### B2. 打卡记录图

要求：

- 参考并尽量复用已有年度热力图的日期网格逻辑和视觉。
- 区分有效打卡日、断签日、无数据日、未来日期。
- 只有现有数据能够可靠区分补卡来源时，才增加补卡视觉状态。
- 点击日期打开详情。
- 断签日期详情与 B1 的备注查看/编辑共用同一套日期详情入口，避免重复实现弹层。
- 不重做一套与现有热力图完全独立的日期系统。

### 阶段 B 修改范围

优先定位：

- `app.js` 中 Task 1 的统计函数、`renderCheckins()`、`renderCheckinOverview()`、`renderCheckinSegments()`
- `app.js` 中现有年度热力图日期生成与点击交互
- `index.html` 中 `checkinOverview`、`checkinSegments`、`checkinFeed` 以及相关热力页结构
- `styles.css` 中 `.checkin-*`、热力图网格、日期详情弹层相关样式
- `S` 初始化、兼容加载、`persist()` 及现有导入/导出序列化路径

禁止：

- 执行心情补卡
- 执行最终全局收尾
- 重构无关模块
- 再次拆分 `app.js`
- 改变 localStorage 核心字段
- 改变 GitHub Gist 加密协议
- 全局格式化

### 阶段 B 验证

至少验证：

1. 连续打卡 → 断签 → 再连续打卡时，断签日期正确。
2. 断签日可新增备注，刷新后仍存在。
3. 备注可编辑、删除。
4. 老数据没有备注字段时正常打开。
5. 打卡记录图能区分打卡、断签、未来/无数据。
6. 点击日期详情正常。
7. 年度边界、跨月、跨年日期不明显错误。
8. 页面现有年度热力图、Task 2 历史列表不被破坏。
9. localStorage、导出/导入和 Gist 序列化路径没有被意外改坏。
10. 移动端布局没有明显破版。

完成后只 commit/push 当前分支，等待 ChatGPT Review，不合并 `main`。

提交信息：

`feat: 增加断签备注与打卡记录图`

## 执行节奏

从现在起采用阶段式协作：

1. ChatGPT 在 `docs/ACTIVE_TASK.md` 指定当前阶段。
2. Codex 在一个分支和一次上下文中完成整个阶段。
3. Codex 完成后一次 commit/push。
4. ChatGPT 直接从 GitHub Review。
5. 只有 Review 发现问题时，Codex 才在同分支修复并再次 push。
6. Review 通过后再合并到 `main`。

用户不需要在 ChatGPT 与 Codex 之间复制代码或截图代码 diff；只有视觉/交互验收确实需要人工判断时才截图或手动测试。
